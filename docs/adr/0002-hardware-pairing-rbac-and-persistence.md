# ADR 0002: Hardware OTP Pairing, RBAC Hierarchy & System Settings Persistence

## Status
Accepted

## Context
Following the core Multi-Tenant Isolation decisions in ADR 0001, clear operational boundaries are required for hardware scanner device pairing, role-based access control (RBAC), and persistent system settings storage to support high-throughput campus deployments.

## Decisions

1. **Stateless Hardware OTP Pairing Bound to `institution_id`**
   - Entrance scanner hardware (laptops, mobile turnstiles) pairs using a 6-digit one-time passcode (OTP) generated by an Institution Admin.
   - The OTP exchange issues a hardware `device_token` bound permanently to `institution_id`, allowing headless entrance scanning without keeping administrator account credentials logged in on shared hardware.

2. **4-Tier Strict Role-Based Access Control (RBAC)**
   - `super_admin`: Platform-wide telemetry, institution onboarding, global maintenance controls, and cross-tenant scanner fleet diagnostics.
   - `admin` (Institution Admin): Full management of campus departments/clubs, student/faculty rosters, scanner devices, and campus events.
   - `org_admin` (Club/Department Head): Scoped management of assigned organization, club member rosters, and club events.
   - `student` / `staff` / `marshal`: Personal biometric enrollment, attendance history, and session check-in scanning.

3. **Database Persistence for System Settings & Audit Logs**
   - Global system status, maintenance windows, and campus broadcast scopes are persisted in a dedicated database table (`system_settings`).
   - Administrative actions (institution onboarding, account toggles, status updates) are recorded in an immutable `audit_logs` database table.

## Consequences
- **Positive**: Prevents administrator credential exposure on entrance hardware; enforces clean RBAC boundary isolation; ensures system settings survive server reloads and sync reliably across load-balanced environments.
- **Negative**: Requires database migration for `system_settings` and `audit_logs` tables.
